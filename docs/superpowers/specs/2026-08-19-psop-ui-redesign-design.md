# PSOP 巡检主流程 UI 重设计

## 目标

在不改变现有 Rokid 眼镜连接、语音、拍照回传、媒体上传、PSOP 后端和 WebSocket 业务链路的前提下，将五个核心页面统一为已确认的浅色巡检界面：

1. 首页
2. 连接眼镜
3. 选择巡检技能
4. 巡检执行
5. 历史记录

本轮不新增账号、个人中心、结构化报告、导出报告、手动跳步骤或手动结束巡检能力。

## 视觉系统

- 固定浅灰页面背景、白色卡片、蓝色主操作。
- 蓝色用于主操作和当前步骤；绿色用于已连接/成功；橙色用于等待用户操作；红色用于失败。
- 使用统一圆角、描边、卡片内边距、状态标签和进度条。
- 保持现有首版的轻量留白，避免引入厚重阴影或多余页面变体。

## 页面和导航

### 首页

- 展示眼镜连接摘要、最近巡检和技能/历史快捷入口。
- 连接后尝试显示眼镜电量；仅在 SDK 返回有效值时显示，取值失败或无值时隐藏。
- 有运行中巡检时，主按钮显示“继续巡检”并进入该任务；无运行中巡检时显示“开始巡检”并进入技能选择。
- 保留现有底部导航视觉：首页进入首页，任务进入技能列表，历史进入历史列表。我的入口本轮不新增页面或业务。

### 连接眼镜

- 保留已保存设备、附近设备列表、名称、MAC 地址、RSSI、连接/重连和帮助入口的首版布局。
- 扫描中仅显示一个停止扫描主操作；扫描停止后根据设备列表显示重新扫描和清空列表。
- 已发现设备时不显示“请确保眼镜已开机”的空扫描提示。
- 已连接设备电量遵循首页相同的可选展示规则；扫描设备列表不显示电量。
- 权限、蓝牙关闭、连接中等为同一页面的状态切换，不新增风格不同的独立页面。

### 选择巡检技能

- 使用既有技能列表、刷新和搜索能力。
- 加载失败、列表为空、搜索无结果作为列表区状态切换。
- 技能名称为必显字段。分类、步骤数、预计时长为可选字段：接口缺少数据时隐藏相应元素。
- 分类筛选仅在实际有分类数据时启用；否则仅保留全部列表和搜索。

### 巡检执行

- 顶部展示任务名称、连接状态；任务卡展示实时完成数、百分比、当前阶段和阶段摘要。
- 进度条、完成数和百分比必须使用同一份 `task-status` 数据，保持一致。
- 保留既有对话、语音、文本输入、相册上传、眼镜硬件拍照回传和媒体查看能力。
- 后端要求拍照时，页面引导“请按眼镜拍照键”，并在同一页面显示回传、上传、成功和失败状态。
- 不新增手动“下一步”或“结束巡检”；后端根据提交的语音、文字或媒体输入推进任务。
- 右上角无对应行为的图标不展示。

### 历史记录

- 使用运行中、已完成、已中止、已取消状态筛选。
- 优先使用现有 `GET /runs` 在不传 `skill_id` 时查询全局历史，并用技能列表映射技能名称。
- 若运行环境不支持无 `skill_id` 查询，则降级为当前已选技能范围内的历史列表，并在界面中标明当前技能。
- 筛选结果只显示当前状态下实际返回的任务；运行中任务可继续，终态任务仅查看历史内容。
- 不新增报告详情或导出动作。

## 数据和状态约束

- 眼镜电量来自 `getGlassInfo` 或电量监听；无有效数据时不显示。
- RSSI 仅在扫描结果可用时展示。
- 首页运行中任务、巡检进度、阶段状态和对话内容以既有 Repository、`TaskStatusResponse` 和 WebSocket 事件为准。
- 失败和空状态不阻塞其它页面的正常访问。

## 实现边界

- 保留既有 Activity、ViewModel、Repository、Rokid CXR SDK 和后端 API。
- 提取 PSOP 专用 Compose 样式和可复用组件，避免五个页面分别硬编码相似样式。
- 普通状态变化通过同一页面的 Compose 状态渲染实现，不新增 Activity。
- 我的页、报表、导出、手动终止、后端新字段和后端新接口不在本轮实现范围内。

## 验证

- 编译 Android debug APK。
- 覆盖首页、连接、技能、执行、历史的关键可组合状态。
- 确认扫描按钮、技能加载/搜索、运行中任务恢复、任务状态更新、语音/媒体入口和历史筛选不会改变现有业务链路。
- 对依赖实机或后端的数据采用有值展示、无值隐藏或降级策略。
