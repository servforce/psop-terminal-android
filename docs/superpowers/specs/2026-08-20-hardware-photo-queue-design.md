# 眼镜硬件拍照回传串行化

## 目标

保证眼镜端拍照键触发的媒体回传在连续回调、同步超时和 P2P 重建时始终串行执行：每张已创建的“上传中”消息都必须进入成功或失败终态，且正常排队的眼镜照片继续被回传和上传。

同时移除历史记录列表中运行中任务卡片右下角的“继续”提示文字，保留卡片点击后继续巡检的行为。

## 设计

- 将眼镜 `MediaFilesUpdateListener` 的入口收敛到主线程处理。
- 在入口处同步建立“拍照轮已占用”标记，再启动 3 秒写盘等待；任何在此之后到达的眼镜照片回调只增加待处理计数，不得创建第二个同步协程。
- 当前轮完成、失败或被终止时统一释放入口占用；若有待处理照片，复用现有排队机制启动下一轮。
- 为每一轮保存独立的消息 ID 与轮次 token。发生超时、接管或替换时，旧轮若已创建消息而无法继续，必须将其更新为失败，不能遗留 `uploading`。
- 保留当前 P2P 同步、空同步、文件同步超时、上传重试和上传后重建逻辑；本轮不改变后端接口、图片压缩策略或眼镜端拍照交互。
- 从 `HistoryRunCard` 中删除运行中状态的“继续”文本节点；整张卡的点击回调和状态标签保持不变。

## 验证

- 编译 `:app:compileDebugKotlin`。
- 静态检查：连续两次媒体回调只会产生一条在途同步链，第二次进入待处理计数。
- 静态检查：同步失败、超时和协程中断路径均让对应消息离开 `uploading`。
- 手工实机验证：连续按眼镜拍照键，确认每张照片要么上传成功，要么显示明确失败，不出现永久转圈；历史记录运行中卡片不再显示“继续”。
