# 首页巡检选择规则

## 目标

让首页“继续巡检”和“最近巡检”准确反映用户最近的操作，不再依赖后端运行列表的返回顺序。

## 规则

- 用户新建巡检或从历史打开运行中巡检时，应用在本机保存该 `runId` 作为最近打开的巡检。
- 首页“继续巡检”优先读取这个本机 `runId`；仅当它仍是 `running`、`waiting_input` 或 `accepted` 时才继续。
- 若本机记录不存在、对应任务已终态或不在当前运行列表中，则从全部运行中任务按 `updatedAt` 倒序选择最近一条；找不到运行中任务时显示“开始巡检”。
- 首页“最近巡检”独立查询全部状态运行，客户端按 `updatedAt` 倒序排序后展示第一条；它不复用“继续巡检”的任务。
- 时间字段解析失败时，保留后端返回顺序作为稳定降级，不阻塞首页。

## 实现边界

- 只修改 PSOP ViewModel、首页状态和首页卡片的数据绑定。
- 不改动后端 API、历史列表筛选、巡检恢复协议或任务状态定义。

## 验证

- 多个运行中任务且 API 返回乱序时，“继续巡检”仍进入本机最近打开且仍运行的任务。
- 本机记录的任务已结束时，自动回退到更新时间最新的运行中任务。
- “最近巡检”可显示最近已完成/中止任务，不再只显示运行中任务。
- Kotlin 编译与现有首页、历史记录跳转保持可用。
